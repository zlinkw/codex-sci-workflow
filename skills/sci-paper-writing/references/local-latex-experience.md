## Reading, navigation and editing

- Keep the right-hand LaTeX Workshop PDF viewer, default page-width zoom, vertical single-page flow and no fade transition on refresh. Preserve source context-menu forward SyncTeX and PDF double-click reverse SyncTeX. Compile-after-cursor positioning remains enabled; change that preference only when the author asks.
- Enable the Workshop project outline following the editor, figure/table entries and outline-to-PDF synchronization. Prefer this project-wide outline for included files.
- Retain formula/reference/citation hover previews. Citation suggestions show titles with authors, year and venue. Use schema-valid citation filtering fields; the installed version accepts bibtex key, title and other fields, not an authors filter enum. Do not claim unlimited author matching: VS Code limits the filter-text prefix.
- Scope reading settings to LaTeX: bounded soft wrap around 110 columns, font size 16, line height 26, hidden minimap and snippet suggestions first. The manual math Suite below owns guarded Tab outside native suggestion/snippet sessions. Soft wrapping must not rewrite source line breaks.
- User snippets are LaTeX-only and use rfig, rsubfig, rtab, req, rreply and rcontrib. Tab advances through placeholders. Figure/table snippets require the actual compatible packages; do not insert packages or invent results merely to use a snippet. Preserve \item[\textbullet] for contributions. Reply snippets are structure only; exact reviewer quotations, direct answers and real changes follow the reply-writing rules.

## Diagnostics, counts and pasting

- Install/reuse ChkTeX and TeXcount with TinyTeX. Use Workshop linting onType so unsaved warning fixes/suppressions are rechecked automatically; project checks still run on save. Review real warnings before making narrow suppressions. Keep duplicate-label checks. Do not hide compiler warnings globally or treat static linting as proof that the PDF or scientific content is correct.
- ChkTeX hover directly displays 接受建议 → 接受全文此类建议 → 忽略本行警告 → 忽略全文此类警告, both on the squiggle and elsewhere on the orange diagnostic line; do not require opening a Quick Fix submenu first. Single acceptance delegates a supported Workshop fix. Full-file acceptance applies currently reported warnings with the same ChkTeX number in the current file as one undoable edit; it never runs sequential asynchronous fixes at shifting positions. Unsupported/incomplete/overlapping replacements stop the whole batch without partial edits. Do not assume a syntax suggestion is suitable merely because the same number occurs elsewhere. 忽略本行警告 keeps its narrow meaning: append `% chktex N` for that warning type on the line, not disable every check on the line. File ignore adds `% chktex-file N` to the current file only. Ctrl+. retains the same actions as an alternative. Other warning codes/files stay checked. Unsupported automatic fixes (including primitive-TeX warning 41) are shown as unavailable with a reason, not silently suppressed. The custom hover shows only the warning number/title, Chinese cause/recommendation and four actions, never raw English diagnostic text. Standard warnings 1–49 have Chinese explanations; unknown codes direct the user to Problems for detail without inventing a translation. Warning 13 at a title/phrase colon or semicolon normally calls for contextual review/line ignore, not automatic insertion of \@ as if it were sentence-ending punctuation. Preserve native diagnostic messages for native fixer parsing and Problems. VS Code's own diagnostic hover can still display English: there is no supported selective replacement/hiding API in the installed version. Disclose this limit; never claim the native duplicate is gone, inject CSS, patch third-party/program code or disable validation to conceal it. These explicit lint edits are undoable source edits, not review-candidate acceptance, saves, builds or Git checkpoints.
- TeXcount runs on save with a modest interval (configured 5 seconds), and is available manually/context menu. Its count is a working estimate, not a verified venue counting convention. Verify text, headings, captions, included files and revision macros for a final word-limit check.
- Prefer ltex-plus.vscode-ltex-plus for English spelling/grammar. The installed client 15.7.1 uses its matching 18.7.0 local server and bundled Java. Download and verify the actual compatible runtime once; subsequent checks use local LanguageTool, with no remote HTTP service. Keep the enabled language list restricted to latex, default English en-US, and checking on save. Suggestions require author/editor judgment; no automatic prose correction.
- Maintain a small verified scientific dictionary and add actual project terms narrowly, not entire passages. Ignore deleted-text macros where supported. Replacement macros can expose both old/new text to the parser; use selection checking or inspect the suggested passage rather than accepting an old-text warning blindly. Do not infer scientific correctness from grammar checking.
- Use usernamehw.errorlens to show errors and warnings beside source. Keep messages short/delayed, omit info/hints and avoid duplicating LTeX diagnostics inline; grammar underlines and Problems remain available. Keep it scoped to this LaTeX workflow.
- Use tecosaur.latex-utilities for explicit formatted paste (Ctrl+Shift+V), booktabs-style table conversion and image insertion. Keep normal Ctrl+V unchanged and automatic live reformatting disabled. Do not activate its Zotero workflow or a second word-count mechanism. Use the Workshop count as the canonical automatic count.
- Use native Source Control/Timeline only for optional backup history and recovery, not author review. No Git Graph/GitLens installation is required. Review IDs and acceptance belong to original-file cards.

## Manual formatting without Git

- Ctrl+Alt+L / 编辑与排版 → 仅整理缩进 invokes localLatex.formatOnly. Manual only, never on typing, paste, automatic save or Ctrl+S. Requires a trusted local .tex, not Git. Saves indentation without committing, pushing or accepting revisions. Workshop's general formatter remains none.
- tex-fmt proposes indentation only. Align unchanged line payloads before borrowing indentation; retain unmatched/split/merged lines. Preserve original line boundaries, blank lines, nonleading content, comments, BOM and literal blocks. Refuse unsupported space/category-sensitive constructs. One sentence per line is the convention for new prose, not whole-file formatter reflow.
- Recheck editor version before applying; report actual save failures. Git staging/history is untouched. The old combined formatAndCommit registration is commented out, not just hidden. A separate Git backup button follows the conditional backup guide and never formats or accepts text. Old source remains inactive until a later explicit cleanup decision.
