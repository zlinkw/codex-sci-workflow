## Selected-text notes and Codex handoff

Select exact text in the original source, then click the card toolbar's annotation action. It opens the reply editor inside that same card; 保存返修批注 and 取消本次批注草稿 are inside the editor. Ordinary source refresh or association-only updates preserve the same-version unsaved draft; an actual new AI candidate generation replaces that old disposable interaction without forcing a manual close. Saving a note updates that existing card and lower notes only, not every project card; posting still validates its immutable version and exact quote, never silently reanchors it. Right-click → 原文审核与批注 → 批注选中文字, or Ctrl+Alt+Shift+Q, remain alternatives. Without a relevant explicit source selection, the card action defaults to its complete immutable original (or the complete candidate for addition-only work). It must also work when no source editor is active; an unrelated editor selection must not force selecting again. Notes retain ID, original/candidate side, immutable generation, Unicode code-point range, exact quote and request status in the single canonical state.

Public VS Code APIs do not expose selected text inside a rendered candidate comment card. Use the card toolbar’s 编辑候选／划词精确批注 to open the shared compact candidate webview. Its wrapping textarea supports direct candidate editing and exact selected-word/sentence notes, with verified UTF-16/CRLF to immutable Unicode-code-point conversion. Save candidate edits as same-ID rework with discard_annotations=true; this clears disposable old notes but never accepts or replaces the source. No candidate selection is required: by default feedback targets the whole original, or the whole candidate when no original exists. Explicit candidate selection switches to exact candidate feedback; clearing it restores the default whole-item target. Save edited candidate text before adding either kind of feedback. Stale candidate versions or concurrent owner/source changes stop writes and preserve unsaved panel text. Closing the panel requires saving manual edits first; reopening the same candidate reuses its panel. Saving a selected note updates only the corresponding native card. The native comment card itself still cannot expose a selection. Saved notes appear with the card until replaced by authorized AI rework. The handoff includes review ID/file, exact original/candidate for the note generation, current version, selected quote and request text. Comment saving never starts an AI.

Ctrl+Alt+Shift+Enter / 全部批注加入 Codex gathers open notes into a derived UTF-8 request attachment and invokes Codex's native Add File to Chat command. It adds context to the composer only; the author checks and sends. No automatic send, clipboard injection or source-editor paste. Request attachments are snapshots, not another live state table. Ordinary authorized writing requests still automatically read actual current decisions/notes; no special phrase or repeated ID list is required.

## One full-paper PDF in a separate VS Code window

New previews use official floating editor windows sharing the source workbench and Workshop instance, not CLI-created independent workspaces. Keep the PDF on the second monitor; reverse SyncTeX must not first create a source tab in that auxiliary window. Existing full-workspace PDF windows remain on the legacy route until the user closes and reopens them from the source window. Reopening an existing generated PDF does not itself authorize compilation.

Explicit Ctrl+Alt+D / 生成／更新完整论文审核 PDF or its card-toolbar action first generates one derived full-document PDF from current local sources/assets and pending candidates, including uncommitted work. The first successful preview opens a new VS Code window; subsequent generations atomically update that document's same stable PDF under .latex-build/review-diff/current rather than spawning another window. Reopen the existing PDF window through its separate noncompiling command if closed. Build failures preserve the prior successful PDF. Accepted-item updates run in a serialized background queue, coalescing queued requests for the same root; after the last acceptance the same PDF shows the accepted paper without old comparison pairs. This does not accept other candidates or finish a batch. Unchanged verified snapshot inputs reuse the successful PDF without TeX. Review-only incremental builds reuse unchanged latexdiff fragments and the last successful compiler auxiliary/dependency state in a fresh isolated generation. latexmk -gt refreshes TeX/SyncTeX while allowing necessary reference/layout convergence; do not force all bibliography rules, suppress errors, remove figures/references or substitute a partial document. Missing disposable cache causes a cold build. This changes no formal Workshop recipe and makes no universal latency guarantee. This applies only to review PDF; ordinary accepted-source viewing, Ctrl+S save/build and SyncTeX remain unchanged. A card refresh, source toggle, annotation or rejection never regenerates it; only the configured author-acceptance event updates an existing preview automatically. PDF display scope is independent of the candidate's acceptance scope: compare sentences even when one candidate spans a whole paragraph, emit unchanged sentences once, and group only adjacent actually changed prose into one comparison pair. An unchanged sentence or independent environment separates pairs; genuine whole-paragraph rewrites may still form one pair. Each changed display run has one header containing its actual candidate ID and verified reviewer-question IDs (or No linked question), plus source-boundary type (Within paragraph, Inline addition, Paragraph rewrite, New paragraph, or independent environment) and ¶ at a real paragraph start, followed by complete original sentences, a thin gray rule, then complete revised sentences; no duplicated Original/Proposed headings. Separate changed runs from one candidate reuse its ID and associations without splitting stored candidates or decisions. Only changed words are marked. Partial deletions retain the surviving sentence, whole deletions identify the deletion with remaining context once below, and additions identify no corresponding original. One compact styled-example legend appears near the beginning. Indivisible TeX environments remain valid; never duplicate unchanged sentences merely because they are inside a candidate's recorded span.

`abstract`, `quote` and `quotation` are prose containers, not indivisible displays: retain their opening/closing structure and title once while comparing actual changed sentences inside. Do not expand one abstract sentence into a complete old/new abstract merely because it lies in an environment. Equations, figures/tables and other protected environments remain independent balanced units. Insertion, removal or alteration of a container itself still needs a balanced environment comparison; never emit unmatched wrapper fragments. Candidate IDs, acceptance scope and decisions remain unchanged.

The card's 定位到审核 PDF action uses the generated snapshot's real SyncTeX coordinates and a window-targeted VS Code URI callback. It refuses missing/stale generations and PDF/metadata digest mismatches rather than guessing page numbers. Navigation metadata/window registration are bounded technical build-cache files, not author issue tables. The final viewer step is a read-only adapter to Workshop 10.20.0's existing viewer.locate export, not a stable public API or source patch; incompatible versions must report a limitation. Cross-window routing and macOS actual desktop behavior remain author-testing items. Normal source-to-PDF SyncTeX is independent. The author accepted keeping the native comment frame, including its line-number gutter extent, while content remains tightly wrapped inside the editor; do not claim exact frame alignment to source column 1.

Comparison context does not define the displayed boundary. Anchor comparisons to original sentences/environments and actual edit positions before aligning text; do not globally align a paragraph whose several candidates introduce new comments/sentences, then smear IDs across resulting insert/delete rows. Adjacent balanced environments are separate units even without blank lines; an unchanged equation/figure appears once, a changed environment has its own pair, and surrounding prose stays at the actual positional scope, up to one paragraph; never force neighboring prose into a special-format item. Preserve braces, inline math, decimals, abbreviations and citation macros. Genuine additions show Addition only; no corresponding original text in the original slot rather than an empty heading; genuine deletions identify the deletion instead of an empty proposed slot. A displayed change carries its actual single candidate ID. Multiple pending candidates targeting the same original sentence/display produce an explicit consolidation error, not a combined ID label or silent state merge. Resolve them in the author paper conversation; never renumber/accept/reject merely to make PDF rendering proceed. This presentation logic never splits persisted review items or changes decisions.

The preview does not modify real prose/state or decide IDs and requires no Git. It is not two PDFs, an excerpt-only report or a Git historical comparison. Derived source/logs/PDF stay under .latex-build/review-diff. Preamble edits and unsupported template/macro cases must report a preview limitation, not a successful equivalent layout. Normal Workshop PDF remains the authority for the accepted source's exact layout, bibliography and cross references.

## Shortcuts and recovery

TeXScholar reviewStyle settings control display colors, deletion strike, card spacing, legend visibility and candidate-panel typography. These are not AI prose-writing commands and must never insert color macros into formal source or change candidate/selection data. Native frame geometry/fonts remain controlled by VS Code; do not patch its renderer. Changing styles refreshes existing cards/panel in place; review PDF colors apply at the next explicit or configured acceptance update. On a new computer, the plugin's AI setup prompt supplies portable presets and asks the assistant to merge collaboration rules into its actual global writing SKILL, preserving scientific rules and removing duplicates. Detect current tools and paths rather than copying machine settings, credentials, proxies or paper remotes. Copying is not proof of configuration; only the user's explicit configured acknowledgement suppresses later prompts.

When the author has reviewed the batch once, **本轮审完：提交已接收成果并推送私有 GitHub** (`localLatex.finishReview`) commits accepted results only. Remaining rework notes stay local. Successful push compacts finished state and automatically deletes verified unreferenced object-cache files, without archiving or another cleanup question. A failed push never triggers cleanup. Busy writers or cleanup errors stop further deletion and report actual partial results; repeating the action can finish cleanup against the same successful checkpoint without another commit/push. See the [accepted-result contract](local-writing-setup.md#accepted-result-checkpoints) for scope and protections. The normal Git backup entry routes active review ledgers here instead of uploading their runtime DATA. Merely opening cards or saving does not trigger this boundary.

| Operation | Shortcut |

| Accept current location and replace original | Ctrl+Alt+Shift+A |
| Whole-item / selected-source rework note | Ctrl+Alt+Shift+R / Ctrl+Alt+Shift+Q |

Restricted Mode disables executable operations. Reload VS Code after installing an update. Existing schema-1 Git-backed records need one local conversion while their Git objects still exist; explicit legacy-item opening through inlineReviewAt retains the conversion path, restoring pending originals with exact-match checks and retaining IDs, history and notes. Automatic discovery and panel refresh are read-only and do not invoke conversion. Conversion is not author rejection or acceptance. Missing objects or conflicts block migration, never reset state. Git is not required afterward. Old review/history command registrations are deactivated rather than merely hidden; their source is retained inactive/commented until a later explicit cleanup decision.
